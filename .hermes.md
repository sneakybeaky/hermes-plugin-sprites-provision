# Project Rules

Hermes: when working in this repo, follow these rules.

## Environment Setup

Before doing any work in this repo, check if Nix needs to be bootstrapped.
Only do this when ALL of the following are true:

1. A `flake.nix` exists in the repo root
2. You are running on the sprites terminal backend (check: the hostname
   starts with `hermes-session-`, or `SPRITES_TOKEN` is set in the environment)

If both conditions are met and `nix` is not already on PATH:

```fish
curl -fsSL https://install.determinate.systems/nix | sh -s -- install linux --init none --no-confirm
sudo chown -R (whoami) /nix
set -x PATH /nix/var/nix/profiles/default/bin $PATH
echo 'set -x PATH /nix/var/nix/profiles/default/bin $PATH' >> ~/.config/fish/config.fish
```

Notes:
- This is a Fly.io sprite VM running fish, no systemd, user `sprite`.
- Nix runs root-only single-user with `--init none` — no daemon.
- The install is idempotent — if `nix` is already on PATH, skip it.
- On persistent sprites, Nix survives across sessions on ext4. Reinstall
  only on genuinely new sprites.
- After installing, enter the project devshell with `nix develop`.

Do NOT attempt this install on local machines or non-sprite backends.

## Working In This Repo

ALL development work happens inside the Nix devshell:

```
nix develop
```

This provides Python 3, pytest, ruff, black, the sprites-py SDK, and puts
hermes-agent source on PYTHONPATH so the plugin's `agent.*` and `tools.*`
imports resolve. The venv (`.venv/`) is created on first `nix develop` and
persists on the sprite's ext4 filesystem across sessions.

Run tests:
```bash
pytest tests/                         # unit tests (no token needed)
pytest tests/ -m integration         # live integration (needs SPRITES_TOKEN)
ruff check . && black --check .      # lint + format check
```

## Git Conventions

Use Conventional Commits for all commit messages:

```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

Types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `build`, `ci`.
Scope: the affected module (e.g. `sprites-env`, `provider`, `flake`, `tests`).

Examples:
```
build(flake): add Nix devshell with sprites-py and hermes-agent source
feat(sprites-env): add tag reconciliation on sprite resume
feat(provider): thread labels from config into SpritesEnvironment
test(sprites-env): unit tests for provisioning idempotency
```

## What This Plugin Adds Over Upstream

Built on top of `NousResearch/hermes-plugin-sprites` (PR #3 compat fix):

1. **Tagging** — attach labels to sprites at creation time and reconcile
   them on resume via `sprite.update(labels=...)`.
2. **First-creation provisioning** — run a script inside the sprite on
   first creation only (never on resume), guarded by a marker file for
   race-safe idempotency.
3. **Nix flake devshell** — reproducible tooling via `nix develop`.
